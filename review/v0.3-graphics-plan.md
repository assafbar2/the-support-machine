# Graphics proposal for the review edition

This is an editorial proposal, outside the reader-facing manuscript. No illustrations are claimed to be part of the current book.

Use a small, consistent diagram for each gate, with one question and one piece of evidence to leave with. Six related diagrams can reinforce the operating map and help a returning reader find their place. Full-page decorative scenes would add page count without helping the decisions.

| Gate | Suggested diagram | What the reader should understand |
|---|---|---|
| 1 — Diagnose the queue | A queue branching into a product fix, clearer guidance, a repeatable workflow, and human investigation | Classify the customer problem before choosing AI |
| 2 — Choose the machine | A stack showing bought, extended, and internally owned components | Buy versus build is a decision at each layer |
| 3 — Design the guardrails | A read path and a separate action path with permission checks and receipts | Knowing an answer does not authorize an action |
| 4 — Shadow-run the machine | The same case entering a human reference review and an isolated candidate run | Compare evidence without changing live customer state |
| 5 — Launch with direct accountability | A cutover lane with owner roles and a staffed containment branch | Decisive migration and practical recovery belong together |
| 6 — Operate the living system | Customer evidence → review → owned change → release → later outcome check | Feedback must lead to verified improvement |

The highest-value additional graphics would be:

1. **The 16% example.** Start with 100 eligible conversations. Show 40 involving the agent, then 16 reported resolved. Keep the customer-outcome check separate; do not color all 16 as verified success.
2. **The evaluation timeline.** Show the original reported resolution, the 7-day check and the 30-day check, with conversations that have not yet matured left outside each denominator. Place independent answer review on its own track.
3. **The unknown-action branch.** Show authorized intent, attempted execution, provider receipt, and an unresolved effect that must be reconciled or handed off. Include a partial workflow where a completed credit must not be replayed because its confirmation message failed.
4. **From goalkeeper to midfield.** A restrained pitch diagram can show a customer problem intercepted through documentation, product changes, or onboarding, while retaining a human recovery path. Use it once where the metaphor is introduced.

Use high-contrast line art, readable labels, and a common visual vocabulary. Every diagram should work in grayscale and have a concise text equivalent in Markdown and HTML. Place it beside the decision it explains. Prefer a few diagrams readers can use in a meeting over an illustration on every chapter opener.
