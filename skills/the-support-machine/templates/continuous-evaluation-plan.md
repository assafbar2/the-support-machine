# Continuing AI Evaluation Plan

Systems / customer tasks / accountable owner and backup:

## Delayed outcomes

Original resolution event, conversation/account identifiers, definition version, and issue context retained:

Sources, API/export access, retention, channels, and coverage verified:

Same-issue matching rules, evidence, uncertain-match review, and correction history:

7/30-day mature cohort denominators, duplicate-return handling, and reporting date:

Report observed recurrence, confirmed customer outcomes, and uncertainty separately. The windows are proposed defaults; add an appropriate longer cycle when needed. Count original conversations, not return events, in the recurrence rate.

## Independent challenge

Random baseline sample and separate targeted sample:

Comparable task/channel/audience/context across systems:

Reviewer and reference evidence; human calibration set; disagreement and false-positive checks:

If comparing unitQ, Unwrap, or native QA: use the same permitted case packet; test wrong reference answers, unknown outcomes, rubric changes, correction workflow, historical regrading, and exportability. Record actual access and observed behavior.

## Current failure rubric

Grade grounding, customer intent, applicability, completeness, effort, escalation, and action effects. Use pass / fail / insufficient evidence / not applicable with reasons. Include correct-but-weak answers, wrong-task answers, unavailable fixes, repeated advice, and missed boundaries. Never average away an unauthorized action.

## Improvement loop

Finding → diagnosis → owner → change → regression → release → later outcome.

Keep holdout cases fresh; version system and grader; repeat trials where variability matters. Route product, policy, data, retrieval, tool, and staffing failures to their owners. Reserve capacity to do the repair work.
