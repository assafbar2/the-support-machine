# Review rubric and calibration

Grade each applicable dimension pass, fail, or insufficient evidence; use not applicable explicitly. Attach the relevant source, customer condition, or observed action. Preserve a separate consequential-failure flag.

| Dimension | Evidence sought | Failure example |
|---|---|---|
| Intent | The underlying customer job or necessary clarification | Perfect export instructions miss an access-audit objective |
| Grounding | Current authoritative support for material claims | Invented policy or stale API guidance |
| Applicability | Version, plan, permissions, environment and prerequisites | Correct fix unavailable on the customer's SDK |
| Completeness | A usable next step and way to check it | Several links without the necessary instruction |
| Effort | History used; unnecessary repetition avoided | Recommends a step the customer already tried |
| Escalation | Required boundary recognized and useful context transferred | Continues after authority or evidence runs out |
| Action outcome | Provider evidence of the intended effect | Treats a timeout as failure and repeats a credit |

Grade agent conduct separately from customer outcome. A product limitation can block resolution despite a well-handled conversation. An eventual fix can follow poor conduct. A success confirmation and later recurrence may overlap.

## Calibration

Use a small, reviewed case set covering good work, subtle failures, missing context, and mistaken reference answers. Review a portion independently. Compare reasons and consequential disagreement, not merely average scores. Blind provider identity where useful. Record rubric, model, source and system versions.

Keep a random baseline apart from targeted complaints and risky actions. Declare the sample frame, exclusions and task mix; do not call a convenience sample representative. Inspect false positives and false negatives. A fault-finding judge can invent problems.

## Evaluator comparison

Give unitQ, Unwrap, native QA or an internal reviewer the same permitted packet. Check input coverage, context access, unknown grades, rubric changes, human overrides, correction history, historical regrading, exportability, latency and cost. Verify feature access and limits in the current plan. Public feature descriptions are not comparative accuracy results.

## Release and learning

Keep fresh holdouts, include neighboring cases, and evaluate actual effects as well as transcripts. Version every knowledge/configuration change; retain a quarantine or rollback path. Never let a strong average cancel an unauthorized action or consequential missed escalation.
